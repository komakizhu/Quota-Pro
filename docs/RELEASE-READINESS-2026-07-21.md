# 2026-07-21 正式上线前审查与交接

> 历史说明：本文最初包含已废弃的付费皮肤授权、设备码和离线签发流程。Default、Blur、Computer 现均为永久免费内置皮肤，相关流程与工具已经移除。以下仅保留仍适用的通用发布检查。

## 当前决定

**禁止将旧的本地联调包或 `0.1.5` 安装包分发给用户。** 当前发布必须从干净工作树重新构建，并完成安装包、更新器和隐私边界检查。

## 资源与隐私检查

- `效果/` 不得作为生产资源目录。生产代码仅引用仓库内明确纳入版本控制的资源；打包后仍需在新建的临时解包目录中确认没有截图、临时素材、用户文件或维护者本机路径。
- Tauri 未配置将整个 `tools/`、`docs/` 或临时目录打入安装包。最终仍应以产物解包审计为准，不能只依赖 `.gitignore`。
- 当前 UI 和更新地址可能暴露公开的项目身份信息。若产品要求使用中性品牌或组织账号，需在发布前明确并统一应用名称、仓库地址与支持渠道。
- 日志、反馈和发布记录不得包含访问令牌、原始额度响应、用户账号信息或本机认证文件路径。

## 正式发布流程

### 阶段 0：冻结与清单

1. 确认版本号、变更说明和支持平台。
2. 使用干净工作树或受控构建环境；不得把截图、日志、临时目录或本机测试材料纳入提交和产物。
3. 运行前端、Rust、类型检查和格式检查，并记录完整结果。
4. 检查生产代码对临时素材目录和本机绝对路径的引用，结果必须为空。

### 阶段 1：受控构建

1. 确认 `TAURI_SIGNING_PRIVATE_KEY` 与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 等更新器签名配置可用。
2. 构建 release 二进制及 Windows/macOS 安装包；不得用直接覆盖本机可执行文件的方式替代正式产物。
3. 在新的临时目录解包安装包，搜索临时素材、截图、`tools`、私钥、账本和维护者本机路径，结果必须为空。
4. 检查安装包版本、签名/哈希、更新器元数据和发布资产名称。

### 阶段 2：隔离验收

在干净的 Windows 与 macOS 测试环境至少完成：

1. 启动、退出、托盘、开机启动、自动更新和窗口恢复。
2. 默认、Blur、Computer 三种免费内置皮肤的切换与重启恢复。
3. 不同缩放比例、屏幕边缘、展开/收起和自定义尺寸下的布局。
4. 未登录、过期、不可用和网络失败状态；应用不得伪造额度值。
5. 查看 app config、日志和安装目录，确认隐私边界与资源清单符合预期。

### 阶段 3：发布与回滚

1. CI 先创建 draft release；隔离验收与产物审计完成后再人工公开。
2. 发布前保存产物 SHA-256、版本号、验收人和时间。
3. 保留上一正式安装包与更新器 manifest，以便发生启动、更新或兼容性回归时回滚。
